# @yeisme/dsh-3d-director

3D Director bundle for DeepSeek Harness. Mounts the host SceneGraphGateway
(service key `scene3dDirector`) from `@yeisme/dsh-3d-director-host` and ships
the Shot-anchored 3D viewport client face from
`@yeisme/dsh-client-ui-3d-director` as one installable unit
(dsh-3d-director-gltf-workbench-v1, priority 6: 3D viewport embed and
bidirectional selection).

## Installation

```bash
dsh plugin --profile web add @yeisme/dsh-3d-director
```

Or from this checkout:

```bash
dsh plugin --profile web add ./packages/bundle/dsh-3d-director
```

The profile patch (`cordis.patch.yml`) inserts exactly one row —
`id: dsh-3d-director` — and is idempotent on repeat install; uninstall removes
the row and the gateway registration.

## Generated installation metadata

The package manifest, profile patch, and compatibility ledger are generated by
the repository application service rather than maintained as independent
machine files:

```bash
pnpm --dir packages/bundle/dsh-3d-director run generate:metadata
pnpm --dir packages/bundle/dsh-3d-director run check:metadata
```

`dsh.compatibility.json` publishes the DSH compatibility range
(`>=0.1.0-rc.6 <0.2.0`, `capability_probe` strategy), the Host/Client
contribution keys, the ADD-only contract ledger (`dsh.scene-3d.v1alpha1`,
`dsh.scene-3d-context.v1alpha1`), contract/release digests, and the exact
conformance command. Build fails if any generated file drifts from the
code-owned source.

## Service key and seams

- **Host service**: `scene3dDirector` (`SceneGraphGateway`) — scene graph
  read/save/reconcile with base-revision conflict fencing, GLB import/export
  with capability gating, append-only generation change sets. Mounted once per
  root context; repeat `apply()` is a no-op.
- **Prerequisites provided by the deployment/session binding, never by this
  bundle**:
  - `scene3dDirectorExpectedContext` — server-bound tenant/workspace/project
    context (`dsh.scene-3d-context.v1alpha1`). Without it every gateway method
    fails closed (`unavailable`); context is never derived from browser
    parameters.
  - `storageDomain` — the approved storage seam behind the revisioned scene
    store. A save conflict never overwrites, retries, or replaces the writer;
    the caller's draft is preserved and the owner reconciles.
  - `scene3dDirectorGlbByteSource` — GLB byte source (structurally the
    dsh-file-host `FileBinaryReadV1` contract). Raw bytes never enter any
    projection; export leaves only as a bounded base64 payload after the
    capability report proves a lossless export.
- **Client face** (`./client`): a thin re-export of the probe
  (`probeScene3DDirector`), `Scene3DController`, view-model helpers, and the
  `Director3DSurface` / `ShotTimeline` / `Director3DViewport` components.
  Embedding into the drama workbench panes is owned by
  `@yeisme/dsh-client-ui-ai-drama-director`; this bundle registers no views of
  its own. A missing or shape-mismatched remote yields a disabled Surface with
  a reason — no dead buttons.

## Evidence tiers

- **Proven (protocol/fixture tier)**: typed contract tests in
  `packages/host/pane-protocol`, host gateway tests
  (`packages/host/dsh-3d-director`), 50 client tests
  (`packages/client/ui-3d-director`), and this bundle's declaration tests plus
  `smoke:bundle` (module load, no Node-process/browser-global leakage,
  idempotent apply, context-less fail-closed honesty).
- **Not claimed**: real-owner/production conformance. No real storage owner,
  file-host byte source, or session-bound context has been wired here; those
  land with the deployment/session-binding integration and record their own
  redacted evidence under `temp/integration-test-runs/<run-id>/`.

## Behavior

- Probe-first: without the `scene3dDirector` remote or expected context, every
  surface degrades honestly (`unavailable` / `needs_contract` + reason).
- No polling: snapshot + event-driven refresh only; transport loss degrades
  without retry loops.
- `unknown`/conflict results never auto-retry; the owner reconciles and local
  drafts are preserved.
- Evidence and errors carry bounded, redacted reasons only — never URLs,
  tokens, file paths, raw prompts, provider payloads, or private tool
  arguments.
