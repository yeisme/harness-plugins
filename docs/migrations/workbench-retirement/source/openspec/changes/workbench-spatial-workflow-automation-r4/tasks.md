# Workbench Spatial 与 Durable Workflow R4 实施任务

## 执行规则

- R4 只消费 R1 actor/access/delegation、R2 Owner operation/receipt/reconcile 和 R3 Asset/WorkItem/Team/Task/Delivery safe refs；不得创建替代权威或 direct browser Owner call。
- Workflow 首版只允许 spec 中列出的 typed DAG steps；新增任意脚本、dynamic URL、循环或新 step type 必须另立合同/安全评审。
- 新增复杂 Board relation、workflow transition、lease/fencing、idempotency/retry、unknown_accept、approval/revoke race、cancel/compensation与operator intervention时，必须用中文注释说明不变量、失败语义和为何不能简化，不记录完整思维链。
- 生产代码和相邻测试由同一 implementer拥有；独立 test/security/performance/browser reviewer只验证稳定diff。
- integration/system/e2e/performance/fault-injection/soak必须通过evidence runner写六件套，失败保留原退出码并扫描credential/token/raw Owner payload/private path/PII。
