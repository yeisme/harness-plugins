# 创作工作流交互

状态：规格设计，未实现真实跨领域编排。任务归 [工作流 change](../../openspec/changes/dsh-creative-workflow-v1/tasks.md)。画布结构与存储由 [画布 change](../../openspec/changes/dsh-project-canvas-continuity-v1/tasks.md) 维护。

## 编辑入口

支持模板、手动连线与Agent生成草案。模板实例化只产生可检查的草案；引用的模型、动作、资产和版本重新探测，不携带旧授权。Agent只能在指定范围内编辑步骤/参数/连接，并给出可撤销摘要；生成草案不启动任务。

从输出端口拖到输入端口后选择用途，展示可选映射和类型不兼容原因。素材引用边可成一般关系图；只有执行边参与DAG校验和运行。环路显示具体路径并阻止执行，草案仍可编辑；迭代通过新运行或复制分支表达。

## 范围与运行预览

| 范围 | 实际选取 | 范围外输入 |
|---|---|---|
| 单节点 | 当前操作步骤 | 必须已有固定、可用版本 |
| 选中分支 | 选中操作及沿执行边可达下游 | 缺固定输入列为阻塞，不自动补执行上游 |
| 完整流程 | 当前document内所有参与执行的操作步骤 | 外部引用仍需固定版本和权限 |

```text
运行预览
将执行：节点列表 / owner / 主要参数
使用版本：输入资源及选定候选
费用：已知估计 + 未知项（不按零处理）
阻塞：缺输入 / 类型不支持 / 失权 / revision变化 / owner不可用
人工节点：等待审阅的位置
操作：返回编辑 | 确认本次范围
```

确认绑定本次草案revision和owner计划。预览后输入、范围或预算变化必须重新预览。既有owner允许明确未知价格时显示相应确认；拒绝时不以插件确认绕过。单领域操作/内部workflow直接使用领域owner；跨领域由Ordo执行，缺适配在Ordo创建最小任务，不能在插件host写轮询调度循环。

## 执行、暂停与重跑

运行Inspector显示owner run/attempt、真实进展、等待原因、成果和恢复动作。心跳不代替业务进展。运行快照不随草案编辑变化；用户可继续准备下一版。人工审阅点暂停；范围/预算升级重新确认。

上游修改显示影响预览，旧成果仍可查看使用。重跑仅处理用户确认的范围并生成新候选。采用后推进当前选定成果，旧下游版本标记受影响而不自动覆盖。对于partial保留成功子项与receipt；unknown原操作只对账，已确认失败才开放owner允许的重试。

关闭Pane、切换会话或刷新只释放UI订阅，不取消执行；重连按原run和cursor恢复。关闭新工作流能力保留原owner观察/恢复路径，不删除草案或资源。

## 任务与验收

原型验证三种创建入口、输入映射、三种范围预览、人工审阅点与部分失败。执行测试覆盖固定版本、环路、缺输入、费用未知、预览后变更、重复确认、断线、跨项目迟到、失败分支重跑、原计划保持不变。

单领域运行与真实跨领域运行分别验收；跨领域记录Ordo计划与每个owner receipt之间的关联。节点显示成功不代表正式采用或交付。所有证据复用既有runner，不新增工作流账本或证据数据库。
